# Навигатор по университету им. Арабаева

Сайт ведёт студента от ворот университета до двери кабинета в три шага: **город → территория → этаж**.
Тестовая версия: карта территории на 2ГИС, маршруты от трёх ворот до любого здания, план 1 этажа корпуса 1 и путь до кабинета с пошаговыми подсказками.

Стек: Vite + React + TypeScript (strict), карта — `@2gis/mapgl`, стили — CSS Modules и токены в `src/tokens.css`. Своего сервера нет: после сборки получается статический сайт.

## Установка и запуск

Нужен Node.js 18 или новее.

```bash
npm install
cp .env.example .env      # в Windows: copy .env.example .env
```

Откройте `.env` и вставьте ключ MapGL из [Platform Manager 2ГИС](https://platform.2gis.ru):

```
VITE_DGIS_KEY=ваш-ключ
```

```bash
npm run dev       # сайт для разработки: http://localhost:5173
```

Без ключа сайт тоже откроется: вместо карты будет карточка «Карта не подключена», а поиск и план этажа будут работать.

## Как выложить

**Vercel:** New Project → выбрать репозиторий. Framework: Vite, Build: `npm run build`, Output: `dist`.
В Settings → Environment Variables добавить `VITE_DGIS_KEY`.

**Netlify:** Add new site → репозиторий. Build: `npm run build`, Publish: `dist`.
В Site configuration → Environment variables добавить `VITE_DGIS_KEY`.

Ключ подставляется в код при сборке, поэтому после смены ключа сайт нужно пересобрать.

### Важно: ограничьте ключ доменом

Ключ 2ГИС попадает в код страницы, и его может увидеть любой посетитель. Поэтому в кабинете 2ГИС (Platform Manager → ключ → ограничения) разрешите его **только для домена сайта** (например, `arabaev-nav.vercel.app`) и для `localhost` на время разработки. Файл `.env` в репозиторий не попадает (он в `.gitignore`).

## Как устроен проект

```
src/
  types.ts                 типы: Building, Door, Gate, PathNode, Floor, Room, Corridor, Entrance…
  data/                    только данные, без логики
    campus.ts              здания, ворота, двери, вид карты
    paths.ts               граф дорожек территории (проверен заказчиком, не менять)
    buildings/
      index.ts             собирает все этажи автоматически
      k1/floor1.ts         план 1 этажа корпуса 1 и кабинеты
  lib/                     логика без интерфейса, покрыта тестами
    graph.ts               Дейкстра — общий для территории и этажей
    geo.ts                 haversine, ближайшие ворота, ссылка на 2ГИС
    campusRoute.ts         маршрут по территории, метры и минуты
    floorGeometry.ts       двери кабинетов, проекции на коридоры, повороты
    floorRoute.ts          граф коридоров этажа и пошаговые подсказки
    search.ts              поиск кабинетов и зданий
    hashState.ts           состояние маршрута в адресе страницы
  components/              MapView, SearchBar, RoutePanel, GatePicker, EntrancePicker,
                           FloorPlan, StepList, BottomSheet, QuickPicks
  pages/FloorScreen.tsx    экран плана этажа
  hooks/                   адрес страницы, GPS, медиазапросы
  i18n/ru.ts               все тексты интерфейса
  App.tsx, main.tsx, tokens.css
```

Компоненты не содержат координат и номеров кабинетов: всё приходит из `src/data`.

**Ссылка на маршрут.** Текущий шаг хранится в адресе: `#k1-117?from=W&in=north&view=floor`
(`k1-117` — корпус и кабинет, `from` — ворота N/W/E, `in` — вход в корпус, `view=floor` — открыт план). Такую ссылку можно отправить другу.

**Кыргызский язык.** Создайте `src/i18n/ky.ts` с теми же ключами, что в `ru.ts`, и переключайте объект с текстами. Поиск уже понимает кыргызские названия кабинетов, в том числе набранные без букв ө, ү, ң.

## Как добавить этаж или корпус

Заказчик приносит план эвакуации, перерисованный с номерами, и список кабинетов с назначением.

1. Создайте `src/data/buildings/<корпус>/floor<N>.ts` по образцу `k1/floor1.ts` и экспортируйте его через `export default`.
   Укажите контур, коридоры (ось, координата, начало и конец), лестницы, кабинеты и служебные помещения.
   Координаты — в единицах плана, `metersPerUnit` — сколько метров в одной единице.
2. Дверь кабинета ставится посередине стены, обращённой к коридору. Сторона задаётся кодом:
   `NT`/`NB` — верхний/нижний ряд северного блока, `EW`/`EE` — западная/восточная сторона восточного крыла, `SN`/`SS` — северная/южная сторона южного крыла, `W` — помещение в западном торце.
   Коридор для двери выбирается ближайший; для входов в корпус коридор задаётся явно (`corridorId`).
3. Каждой лестнице дайте `id`, общий для всех этажей корпуса (например, `k1-stair-mid`).
4. Для нового корпуса: добавьте на 1 этаж `entrances` и свяжите каждый вход с дверью на карте через `campusDoorId` (id двери из `campus.ts`). Если дверь выбирает студент, поставьте зданию `doorChosenByUser: true`.
5. Поиск подхватит новые кабинеты сам: этажи собираются из всех файлов `buildings/*/floor*.ts`.
6. Запустите `npm test`: тест «у каждого кабинета есть путь от обоих входов» сразу покажет кабинет, до которого не строится путь.

**Что нужно доделать, когда появится 2 этаж** (в тестовой версии этажей выше первого нет, поэтому это не сделано):
переходы между этажами — ребро графа между одной и той же лестницей на соседних этажах, вес 15 м за этаж;
шаг «Поднимись по лестнице на N этаж»; вкладки этажей «1 2 3 4» над планом.
Место отмечено `TODO(этажи 2+)` в `src/lib/floorRoute.ts`.

**3D-модели.** Если университет даст модели корпусов (Blender → glTF), их можно показать поверх карты через `mapgl.GltfModel`. Для этого в `MapView` уже есть проп `models` и интерфейс `BuildingModel` (`src/components/MapView/BuildingModel.ts`); в тестовой версии модели не подключаются.
